# Game Matcher

Standalone matcher bundle exported from `resonalyzer2`.

This project consumes precomputed Rezona/Gamezone query output folders, rebuilds
matcher-ready consolidated indexes locally, and serves a browser UI that maps
freeform game prompts to ranked games.

## Directory Layout

```text
game_matcher/
  index.html
  serve_game_matcher.py
  README.md
  scripts/
    build_gameplay_reverse_index.py
    export_all_queries.py
    refresh_indexes.sh
  fixtures/
    source_outputs/
      run_*/
        manifest.json
        queries/
        summaries/
    consolidated/
      all_queries.json
      master_game_reverse_index.json
      master_game_reverse_index_summary.json
      master_query_to_games_index.json
```

## Input Contract

### Rebuild source input
The rebuild pipeline reads precomputed output folders from:

- `fixtures/source_outputs/run_*/queries/query_*.json`

Each `query_*.json` file must contain, at minimum:

- `query_metadata.query`
- `response.data.items`

Optional metadata preserved when present:

- `query_metadata.category`
- `query_metadata.subcategory`
- `query_metadata.mechanic_family`
- `query_metadata.query_type`
- `query_metadata.priority`

Each result item must either contain:

- a nested `game` object, or
- top-level `game_id`

Game fields consumed when present include:

- `game_id` (required)
- `game_version`
- `name`
- `description`
- `url`
- `cover_url`
- `dynamic_cover_url`
- `screen_orientation`
- `is_public`
- `created_at`
- `updated_at`
- `stats`
- `creator`
- `topic`
- `exact_match`

Feed position is derived from the array order in `response.data.items`.

### Runtime input
The browser UI reads only:

- `fixtures/consolidated/all_queries.json`
- `fixtures/consolidated/master_game_reverse_index.json`

## Output Contract

### Generated by `scripts/build_gameplay_reverse_index.py`
Written to `fixtures/consolidated/`:

- `master_game_reverse_index.json`
- `master_game_reverse_index_summary.json`
- `master_query_to_games_index.json`

Semantics:

- `master_game_reverse_index.json`: full game-centric reverse index used by the matcher
- `master_game_reverse_index_summary.json`: lighter summary view
- `master_query_to_games_index.json`: query-centric index used as the source for vocabulary export

### Generated by `scripts/export_all_queries.py`
Written to `fixtures/consolidated/`:

- `all_queries.json`

Semantics:

- sorted deduped JSON array of valid query strings
- this vocabulary constrains the LLM query-selection step

## Runtime Flow

1. Start the local server
2. Open the browser UI
3. Paste an OpenAI-compatible Chat Completions API key in settings
4. Enter a freeform game prompt
5. The app sends the prompt plus the valid query vocabulary to the Chat Completions API
6. The app ranks local indexed games deterministically in-browser

UI output:

- translated query chips
- ranked game cards
- click-through links to original game URLs when present

## Rebuild Flow

From this `game_matcher/` directory run:

```bash
python3 scripts/build_gameplay_reverse_index.py
python3 scripts/export_all_queries.py
```

Or use:

```bash
./scripts/refresh_indexes.sh
```

## Replace-Fixtures Workflow

### Replace source outputs and rebuild
1. Remove or overwrite contents under `fixtures/source_outputs/`
2. Copy in new `run_*` folders with the same structure
3. Run `./scripts/refresh_indexes.sh`
4. Reload the browser UI

### Replace consolidated outputs directly
If you already have finalized consolidated outputs, overwrite files under:

- `fixtures/consolidated/`

Then reload the browser UI. No rebuild is required.

## Idempotency Contract

Given the same contents under `fixtures/source_outputs/`, running:

1. `scripts/build_gameplay_reverse_index.py`
2. `scripts/export_all_queries.py`

must regenerate the same logical consolidated outputs under `fixtures/consolidated/`.

Dependency chain:

```text
fixtures/source_outputs/run_*/queries/query_*.json
  -> scripts/build_gameplay_reverse_index.py
     -> master_game_reverse_index.json
     -> master_game_reverse_index_summary.json
     -> master_query_to_games_index.json
        -> scripts/export_all_queries.py
           -> all_queries.json
```

## Non-Goals / Out of Scope

This project does **not**:

- perform crawling
- supervise crawling workers
- generate raw `run_*` outputs from the network
- expand the query universe beyond the supplied fixtures

It assumes source output fixtures are produced elsewhere and copied into this bundle.

## CLI Matcher

A Python CLI is available for terminal-based matching with the same local query vocabulary and reverse-index ranking logic used by the browser UI.

### Setup

Create a virtual environment and scaffold a local `.env` file:

```bash
./scripts/setup_cli_env.sh
```

Then edit `.env` and set:

```bash
OPENAI_API_KEY=your_openai_api_key_here
```

### Usage

Run through the launcher script:

```bash
./scripts/run_cli_matcher.sh "funny zombie endless runner"
```

By default, the CLI uses the derived `top800` subset index. Use `--index all` to opt into the legacy full index.

Optional flags:

```bash
./scripts/run_cli_matcher.sh "funny zombie endless runner" --limit 10
./scripts/run_cli_matcher.sh "funny zombie endless runner" --out output/matches.json
./scripts/run_cli_matcher.sh "funny zombie endless runner" --limit 25 --out output/top25.json
./scripts/run_cli_matcher.sh "funny zombie endless runner" --index all
./scripts/run_cli_matcher.sh "funny zombie endless runner" --index all --limit 25 --out output/top25-all.json
```

Behavior:
- loads `OPENAI_API_KEY` from `.env` by default
- translates the free-text prompt into up to 10 valid local queries via the Chat Completions API
- ranks games locally using the `top800` reverse index by default
- uses the legacy full reverse index only when `--index all` is provided
- prints a JSON array to stdout by default
- writes the JSON array to the path given by `--out` when provided

### `--limit` behavior and best-match meaning

The CLI ranks all candidate games and then returns only the first `N` results after sorting.

Examples:

```bash
./scripts/run_cli_matcher.sh "funny zombie endless runner" --limit 1
./scripts/run_cli_matcher.sh "cozy farming game with crafting and pets" --limit 5
./scripts/run_cli_matcher.sh "arcade driving game with drifting" --limit 1 --out output/top-match.json
```

What `--limit 1` means:
- return only the single highest-ranked game
- in practice, this is the "best match" according to this matcher's scoring model

Important nuance:
- the final ranking is deterministic once the translated query list is fixed
- the query translation step uses the Chat Completions API, so the selected queries can vary slightly across runs
- because of that, `--limit 1` is the best match from this system for that run, not a guarantee of an objectively perfect result in all runs

Practical guidance:
- use `--limit 1` when you want one strongest recommendation
- use `--limit 5` when you want to compare the top result against nearby alternatives
- if the top result feels off, rerun with `--limit 5` to inspect whether another highly ranked option is a better fit

Direct Python entrypoint:

```bash
python3 cli/game_matcher_cli.py "funny zombie endless runner"
```

Supported CLI arguments:
- positional `prompt`
- optional `--limit` (default `20`)
- optional `--out PATH`
- optional `--env-file PATH`
- optional `--index {top800,all}` (default `top800`)
