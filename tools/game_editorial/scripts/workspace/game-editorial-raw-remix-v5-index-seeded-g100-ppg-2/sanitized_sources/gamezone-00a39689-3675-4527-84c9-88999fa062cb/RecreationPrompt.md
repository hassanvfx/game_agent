Recreate a browser game called **Orbit Sudoku Grid**, a sleek mobile-friendly Sudoku title that reframes classic number solving as stabilizing futuristic orbital sectors. Build it as a single-page experience with a neon sci-fi presentation: dark space-blue gradients, glowing cyan highlights, glassy menu cards, futuristic display fonts, and crisp HUD elements that feel like a spaceship control interface. The tone should be focused and readable, but with light arcade tension and rewarding payoff.

Structure the experience around a simple flow: a main menu, a difficulty-specific level select screen, active gameplay, and a pause / result modal. The main menu should present three choices—Easy, Medium, and Hard. After choosing one, show a grid of numbered sectors for that difficulty, with locally saved completion markers so cleared sectors appear visibly completed when the player returns. Use about 10 levels for Easy, 10 for Medium, and 25 for Hard.

Each playable level should be a deterministic 9x9 Sudoku puzzle generated from a seed based on the selected difficulty and level number, so the same sector always produces the same board. Generate a full valid Sudoku solution first, then remove numbers according to difficulty: roughly 30 empty cells for Easy, 42 for Medium, and 54 for Hard. Keep the actual gameplay strict and streamlined: the game should know the full solution and compare each attempted placement directly against it.

Render the board on canvas in the center of the screen. Show a top HUD with a pause button, an elapsed timer, and a mistake counter labeled as something thematic like **Glitches: 0/3**. At the bottom, render an on-screen horizontal numpad with digits 1 through 9. The control scheme should be touch-first and pointer-friendly: tap a grid cell to select it, then tap a number on the numpad to place that value. Pre-filled cells must be locked and visually distinct from player-entered values. When a cell is selected, highlight its row, column, and the selected square; if the selected cell already contains a value, lightly highlight matching numbers elsewhere in the grid.

Make the challenge loop feel brisk and game-like rather than like a plain Sudoku worksheet. A correct entry should fill the chosen cell, play a satisfying placement sound, and emit a small burst of glowing particles from that tile. A wrong entry should immediately count as a mistake, trigger a fail sound, and briefly shake the board. The player loses the run after 3 mistakes, which should open a modal with a retry option for the same sector. If the player successfully fills the entire grid, show a celebratory sector-cleared state with confetti, a win sound, and a completion message like **Sector stabilized**. Winning should save that sector as completed in local progress storage.

Use DOM overlays for the menu, level select, HUD wrappers, and modal dialogs, but keep the active board and numpad rendered directly on canvas for a polished custom-game feel. Include short animated feedback cards or toasts for fail and win events, and add background music during active runs plus menu / pause / resume / fail / win sound effects. Make sure the layout is responsive and comfortable on phones, with safe-area-aware padding and a clear visual hierarchy. The final result should feel like an arcade-styled sci-fi Sudoku game: deterministic, level-based, touch-friendly, and visually premium without adding extra mechanics like pencil marks, hints, or freeform notation.
