# Blueprint

## High-level code structure
The project is a single-file browser game implemented in `index.html` with embedded CSS and JavaScript. Its structure is:

- **HTML shell**
  - Fullscreen `<canvas>` for rendering the board and pieces
  - Overlay UI layer containing:
    - start screen
    - HUD with piece counts and turn indicator
    - sound toggle
    - game-over screen
    - toast notifications
    - animated GIF feedback elements
- **CSS presentation**
  - Neon sci-fi / arcade styling
  - Mobile-safe overlays with safe-area padding
  - Responsive HUD/cards/buttons for touch screens
- **JavaScript systems**
  - `CONFIG`: board size, animation speed, AI delay, palette
  - `MEDIA`: approved remote audio/GIF mappings
  - `AudioSys`: BGM/SFX preload, play, toggle
  - `GifSys`: capture and endgame reaction display
  - Hex-grid helper math:
    - `HEX_DIRS`
    - `hexDist`
    - `hexRound`
  - `Game` class:
    - canvas setup
    - input handling
    - game state
    - board initialization
    - move generation
    - line-of-3 rule enforcement
    - surround/capture resolution
    - AI decision-making
    - rendering loop
    - UI updates

## Game loop / state model
The game uses a continuous animation/render loop driven by `requestAnimationFrame`, while gameplay itself is **turn-based**.

### Core state fields
`state` contains:
- `pieces`: all active stones/pawns on the board
- `turn`: `"player"` or `"ai"`
- `selectedId`: currently selected player piece
- `validMoves`: legal destinations for the selected piece
- `animating`: whether a move resolution is in progress
- `gameOver`: whether the match has ended

### Turn flow
1. Player starts with 6 pieces; AI starts with 6 pieces.
2. Player taps one of their pieces.
3. Valid destinations are computed and highlighted.
4. Player taps a legal hex to move.
5. After a short delay, end-of-turn resolution checks all pieces for surround captures.
6. Captured pieces are removed simultaneously.
7. Win/loss is checked:
   - player wins if AI is reduced to 2 or fewer pieces
   - player loses if their side is reduced to 2 or fewer pieces
8. If the game continues, turn swaps to AI.
9. AI evaluates all legal moves and performs the best-scoring one.
10. Resolution repeats and turn returns to the player.

### Movement model
- Board is a **radius-3 hex grid**
- Most pieces move **1 hex in any of 6 directions**
- A piece occupying the center hex `(0,0)` has special mobility and can slide farther along lines up to the board limit
- Moves cannot land on occupied cells
- A move is illegal if it causes the mover’s team to end the move with **3 allied stones aligned in a row**

## Player goals
The player controls the **Red Clan** and tries to:
- reposition pieces on the hex board
- surround enemy pieces with adjacency pressure
- trigger removals by leaving enemy pieces adjacent to at least 3 opposing pieces
- avoid exposing their own pieces to the same fate
- respect the anti-formation rule forbidding a 3-stone allied line after moving

Immediate tactical goal:
- create local encirclement opportunities

Match goal:
- reduce the opponent to **2 stones or fewer**

## Interaction pattern
The interaction model is simple, readable, and touch-friendly:

- tap/click a friendly piece to select it
- see legal move markers
- tap a highlighted cell to move
- invalid attempts clear selection and may show a toast:
  - “No 3-stone line allowed”
  - “That path is blocked”

There is no drag movement, no menus beyond start/restart, and no real-time dexterity requirement. The game is a compact tactical duel designed for quick sessions on desktop or mobile.

## Core systems
### 1. Hex board system
The board is represented in axial hex coordinates `(q, r)`. Valid cells are those within the configured radius.

### 2. Selection and move generation
For a selected piece, legal moves are generated by stepping through hex directions and filtering out:
- off-board targets
- occupied targets
- moves that would violate the no-3-in-a-row allied formation rule

### 3. Capture / elimination system
At end of each move, every piece is inspected. If a piece has **3 or more adjacent enemies**, it is removed. This applies to both teams and can remove multiple pieces in the same resolution step.

### 4. AI system
The AI is a lightweight heuristic bot that:
- simulates legal moves for each AI piece
- heavily rewards moves that would eliminate player pieces
- heavily penalizes suicidal placements
- slightly prefers central positioning
- adds a small random term to avoid deterministic repetition

### 5. Feedback / juice layer
The game adds arcade dressing through:
- ambient looping music
- click/move/block/capture/win/lose sounds
- capture and endgame GIF reactions
- glowing highlights, animated tokens, neon HUD cards, and toast messages

### 6. Win/loss and restart flow
The match ends when one faction falls to 2 or fewer pieces. A themed game-over screen appears with restart support.

## Inferred genre / gameplay shape
This is best understood as a **turn-based abstract strategy board game** presented with a stylized arcade skin.

### Gameplay shape
- small-board tactical duel
- deterministic spatial rules with minor AI randomness
- short rounds
- easy to learn, harder to optimize
- focused on positioning, threat creation, and avoiding self-traps

### Closest abstract identity
It feels like:
- a **hex-grid strategy puzzle duel**
- a **surround-capture tactics game**
- an **abstract board skirmish** rather than a simulation or action title

## Heuristic read of the intended experience
The intended player fantasy is not military realism but a quick “clan siege” mind game:
- readable tactical choices
- satisfying surround captures
- constant tension from the anti-line rule
- quick rematches
- flashy audiovisual rewards layered on top of minimal but elegant board logic
